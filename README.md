# danielviedienin.com

Трёхъязычный (EN / UA / RU) Jekyll-сайт-визитка. Статика, хостинг — Netlify.

## Быстрый старт (локально)

```bash
bundle install
bundle exec jekyll serve
```

Сайт откроется на `http://localhost:4000`. Корень редиректит на `/en/` только на Netlify
(через `_redirects`) — при локальном запуске открывайте `/en/`, `/ua/` или `/ru/` напрямую.

## Деплой на Netlify

1. Запушьте репозиторий на GitHub.
2. В Netlify: **Add new site → Import an existing project**, выберите репозиторий.
3. Build command: `bundle exec jekyll build`, Publish directory: `_site` (уже прописано в `netlify.toml`, менять не нужно).
4. В **Domain settings** подключите `danielviedienin.com` (файл `CNAME` уже указывает на него).
5. **Site settings → Forms** — включится автоматически: обе Netlify Forms-формы (`contact`) обнаружатся при первом билде.

## Структура

```
_config.yml         конфиг Jekyll (языки, permalink, плагины)
Gemfile              зависимости
netlify.toml          команда сборки
_redirects            редиректы (корень → /en/, /uk/* → /ua/*)
_data/translations.yml  строки интерфейса (меню, футер) на 3 языках
_layouts/             default / home / page / post / note
_includes/            head, header, footer, переключатель языков, favicon
assets/css/style.css   вся дизайн-система одним файлом
assets/js/main.js      бургер-меню + переключатель языков
en/ ua/ ru/            по 10 страниц в каждой (главная, about, cv, offer, blog, notes, articles, contact, thank-you, cat)
_posts/                статьи (Articles) — общая коллекция для всех языков, см. ниже
_notes/                заметки (Notes) — то же самое
assets/files/CV-Daniel-Viedienin.pdf   сгенерированное резюме (EN)
assets/images/          favicon-комплект (сгенерирован, см. «Плейсхолдеры»)
assets/img/              фото-плейсхолдер и иллюстрация кота (см. «Плейсхолдеры»)
```

## Как добавить пост

**Статья (Articles, 1500–3000 слов):** новый файл в `_posts/`, имя `ГГГГ-ММ-ДД-название.md`:

```yaml
---
title: "Заголовок"
lang: ru        # en / ua / ru
date: 2026-09-20
excerpt: "Опционально — короткое превью"
---
Текст статьи в Markdown.
```

**Заметка (Notes, 300–500 слов):** то же самое в `_notes/`, но без `excerpt`, `layout` подставится
автоматически (`note`). Дальше просто `git push` — Netlify пересоберёт сайт, и пост появится на
`/{lang}/blog/` и `/{lang}/articles/` (или `/notes/`), отсортированный по дате, новые сверху.

Технический нюанс: у отдельных статей/заметок нет языкового префикса в URL (см. пункт про permalink
ниже) — только у хаб-страниц (`/en/blog/`, `/ua/blog/`…).

## Плейсхолдеры — что нужно заменить перед запуском

Все три ниже — рабочие заглушки, сайт с ними полностью функционален, но это не финальный контент:

- **`assets/img/daniel-photo.svg`** — абстрактный силуэт вместо фото. Реального фото Данила у меня
  не было, а генерировать «фейковое» фото реального человека я не стал. Замените на настоящее фото
  (`.jpg`/`.png`) и поправьте путь `photo:` в front matter `en/index.md`, `ua/index.md`, `ru/index.md`.
- **`assets/img/cat.jpg`** — сгенерированная иллюстрация кота (не фотография Тузика). Просто
  замените файл на реальное фото с тем же именем — переписывать шаблоны не нужно.
- **`assets/images/favicon*`, `apple-touch-icon.png`, `android-chrome-*.png`, `site.webmanifest`** —
  сгенерированная заглушка (монограмма «DV»), как и просили в промпте («если файлов не будет —
  используй стандартный .ico как заглушку»). Если у вас уже готовы файлы с Favicon.io — просто
  замените содержимое `assets/images/` этими файлами (имена уже совпадают).
- **Google Analytics** — в `_includes/head.html` в самом низу закомментированный блок gtag.js,
  впишите свой `G-XXXXXXXXXX` и раскомментируйте.

## Резолвнутые несоответствия

Промпт сам просил: «если найдёшь противоречие — не спрашивай, выбери вариант и примени везде,
в конце перечисли, что и как решено». Вот полный список.

### 1. `/ua/` vs `/uk/`
П.1 промпта прямым текстом требует `/ua/` и явно запрещает `/uk/`. При этом реальные блоки
Notes, Articles, Blog(UA), Thank-you, Cat, а также таблица URL страницы About — везде используют
`/uk/` и `lang: uk`. Применил `/ua/` и `lang: ua` везде без исключений (это и есть явно указанный
вариант, а не просто «более частый»). Для старых ссылок на `/uk/*` в `_redirects` добавлен
301-редирект на `/ua/*` — на случай, если где-то в промпте или переписке уже фигурировал `/uk/`.

### 2. Гарантированно битые ячейки таблиц (копипаст-артефакты)
- Футер, копирайт (EN): «Danylo Viedienin... / (UA) «» (RU)» — явно склеенные обрезки трёх ячеек.
  Взял чистый шаблон по образцу UA/RU-ячеек: «© 2026 Daniel Viedienin. Built with Jekyll & Netlify.»
  (имя «Daniel», как везде в EN-версии, а не «Danylo»).
- Главная, блок CTA, кнопка (EN/UA): «CONTACT (→ /en/contact) / Зв'язатися (UA, → /ua/contact/) //)»
  и «Повна історія →» без открывающей кавычки. Взял чистые варианты: EN «CONTACT» → `/en/contact/`,
  UA «Повна історія →» → `/ua/about/`.
- Незаполненная черновая таблица «Кнопки навигации» в разделе 6 (только 3 EN-строки, без UA/RU) —
  не использовалась, так как рядом в том же разделе есть полная, заполненная таблица навигации —
  взял её.

### 3. Пропущенный абзац (About, блок «Навіщо це все? / Зачем это всё?»)
В EN у блока 3 абзаца (есть абзац «I don't need a title…»), в UA и RU — только 2, этого абзаца нет
физически. Дописывать перевод сам не стал (прямой запрет в промпте, п.3) — оставил как в
источнике и добавил HTML-комментарий прямо в `ua/about.md` и `ru/about.md` рядом с этим блоком.
Стоит просто перевести недостающий абзац и вставить самостоятельно.

### 4. Русский текст сертификатов на самом деле украинский
В `ru/cv.md`, группа сертификатов «Критическая помощь» — в промпте RU-колонка для этой группы
дословно продублирована из UA-колонки (украинские словоформы: «дорослого», «розширені» и т.д.).
Оставить украинский текст на русской странице резюме означало бы реально сломать страницу, поэтому
это единственное место, где я не просто оставил текст как есть, а пересобрал русский вариант — на
основе уже корректной EN-версии и терминологии, которая уже используется в остальных (написанных
правильно) группах сертификатов на этой же RU-странице. Отмечено HTML-комментарием прямо в файле.
Строки:

> Менеджмент критического взрослого пациента и расширенные реанимационные мероприятия у взрослых
> (27 ч, 2025); Менеджмент критического травмированного пациента (15 ч, 2025); Менеджмент
> критического педиатрического пациента (10 ч, 2025); Менеджмент критического травмированного
> пациента (16 ч, 2026) – углублённый уровень.

Пожалуйста, перепроверьте формулировки — я не медик и не носитель профессиональной русской
клинической терминологии на уровне практикующего специалиста.

### 5. Форма обратной связи: два взаимоисключающих описания
В описании назначения страницы Contact сказано «форма без перезагрузки, с сообщением об успехе
на странице». Но там же ниже дан полностью готовый контент отдельной страницы Thank-you на 3
языках с инструкцией добавить `action="/xx/thank-you/"` в форму. Второй вариант описан полностью и
с кодом, первый — одной фразой без деталей. Реализовал через `action=".../thank-you/"` (классический
Netlify Forms redirect). Также добавил скрытое поле `form-name` в каждую форму (в исходном HTML-
сниппете его не было) — без него Netlify иногда не распознаёт форму при статической сборке.

### 6. Дублирующийся заказчик PDF-резюме
Кнопки «Скачать PDF» на всех трёх языковых версиях CV ведут на один и тот же файл
`/assets/files/CV-Daniel-Viedienin.pdf` (так в промпте — не описка, все три ячейки одинаковы).
Сделал один PDF на английском (сгенерирован из содержимого EN-страницы CV). Если нужны отдельные
PDF на UA/RU — сделайте `CV-Daniel-Viedienin-ua.pdf` / `-ru.pdf` и поменяйте ссылку на
соответствующей странице (`en/cv.md`, `ua/cv.md`, `ru/cv.md`).

### 7. Плагин jekyll-multiple-languages-plugin — убран после ошибки сборки
Изначально был указан в Gemfile/`_config.yml`, как и просили. Но реальная механика в промпте —
это ручная мультиязычность (`page.lang` + `_data/translations.yml` + отдельные папки
`/en/ /ua/ /ru/`), а не собственные Liquid-теги этого плагина (`{% t %}` и т.п.) — их сайт нигде
не использует. При первом деплое на Netlify сборка упала на `bundle exec jekyll build` без
подробностей в логе — это малоподдерживаемый гем, и он был первым кандидатом на поломку
резолвинга зависимостей. Убрал его из Gemfile и `_config.yml` полностью — функционально сайт
ничего не теряет. Если после этого сборка всё ещё падает, смотрите раздел «Если сборка снова
упадёт» ниже.

### 8. «Пасхалка»: exclude vs noindex
В разделе про страницу `/cat/` предлагались два варианта скрыть её от поиска: (а) добавить в
`_config.yml` → `exclude`, либо (б) `<meta name="robots" content="noindex">`. Вариант (а) физически
удаляет страницу из сборки — тогда ссылка «кот» в футере вела бы в никуда, это сломало бы саму
пасхалку. Использовал только (б): `noindex: true` в front matter → мета-тег подставляется в
`head.html`. По той же логике `robots.txt` не блокирует `/cat/` через `Disallow` (Google сам не
рекомендует сочетать `Disallow` с `noindex` — краулер тогда не увидит сам тег).

### 9. Мелкие опечатки в исходном тексте — оставлены как есть
Не трогал по прямому запрету «не вносить изменения в уже готовый текст». Стоит поправить у себя:
- RU, About, блок «Продажи и переговоры»: «искал способы договариваться **с с** людьми» — задвоенный предлог.
- RU, About, блок «Психология и коммуникация»: «…«здесь и сейчас».Это не...» — пропущен пробел после кавычки.
- RU, About, блок «Что дальше?»: открывающая кавычка `"`, закрывающая — `»` (разный стиль в одной паре).
- RU, Offer, блок Sales Engineer: «с технической **сторон**» — видимо, «стороны».

## Технические примечания

- **Permalink статей/заметок без языкового префикса.** В промпте прямо задан
  `permalink: /blog/:year/:month/:day/:title/` (без `/en/`, `/ua/`, `/ru/`) — так и сделано; для
  `_notes` по аналогии `/notes/:year/:month/:day/:title/`. Из-за этого переключатель языков на
  странице конкретного поста/статьи не может подставить «эквивалентную» страницу на другом языке
  (такой попросту не существует) — в этом случае он ведёт на `/{lang}/` соответствующего языка.
- **Все внутренние URL — с завершающим слэшем** (`/en/about/`, не `/en/about`) — так везде в
  таблицах промпта, кроме нескольких мест, где слэш пропущен (см. п.2 выше) — унифицировано.
- **hreflang** проставляется автоматически в `<head>` для локализованных страниц (не для
  постов/заметок — им не с чем сопоставлять перевод).
- Добавлен `jekyll-sitemap` (не был в списке плагинов) — чтобы `robots.txt` со ссылкой на
  `sitemap.xml` действительно на что-то указывал. Безопасное дополнение, не конфликтует ни с чем.
- Добавлен `404.html` — не был запрошен явно, просто чтобы страница отсутствия не отдавала
  стандартную заглушку Netlify.

## Если сборка на Netlify снова упадёт

1. Откройте неудачный деплой → вкладка Deploy log — если сообщение об ошибке обрезано (как было
   при первом деплое), временно включите подробный вывод: в `netlify.toml` замените команду сборки на
   ```
   command = "bundle exec jekyll build --trace"
   ```
   закоммитьте, запушьте, дождитесь нового деплоя и пришлите мне лог целиком — `--trace` покажет
   точную строку и гем, на которых всё падает.
2. Частая причина — несовместимая версия гема. Можно закрепить версию Ruby явно в самом Gemfile
   (`ruby "3.2.2"` первой строкой) — иногда это само по себе чинит проблему резолвинга.
3. После того как сборка пройдёт хотя бы раз успешно, верните `netlify.toml` обратно на
   `bundle exec jekyll build` (без `--trace`) — так лог остаётся чистым при обычных деплоях.
